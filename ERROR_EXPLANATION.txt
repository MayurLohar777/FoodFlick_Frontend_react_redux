1. CRITICAL ERROR: BLANK WHITE SCREEN ON APP STARTUP
--------------------------------------------------------------------------------
Location:
  File: src/router/PublicRoutes.jsx
  Lines: ~23-38

Problem:
  In `src/router/Router.jsx`, `PublicRoutes` was used as a layout route wrapper 
  for nested public pages:
    {
      element: <PublicRoutes />,
      children: [
        {
          element: <AuthLayout />,
          children: [
            { path: ROUTES.LOGIN, element: <LoginForm /> },
            { path: ROUTES.REGISTER, element: <Register /> },
          ]
        }
      ]
    }
  However, `PublicRoutes.jsx` was defined as:
    const PublicRoutes = ({ children }) => {
      ...
      return children;
    };
  Because React Router does NOT pass child routes as the `children` prop to layout
  elements, `children` was `undefined`. When `PublicRoutes` returned `undefined`,
  React rendered nothing, leaving the screen completely blank and preventing the 
  Login and Register pages from mounting.

Solution:
  Imported `Outlet` from `react-router-dom` and updated `PublicRoutes` to render
  `<Outlet />` when child routes are present:
  
  [BEFORE]
    const PublicRoutes = ({ children }) => {
      if (isAuthenticated) {
        return <Navigate to={ROUTES.HOME} replace />;
      }
      return children;
    };

  [AFTER]
    import { Navigate, Outlet } from "react-router-dom";
    
    const PublicRoutes = ({ children }) => {
      if (isAuthenticated) {
        return <Navigate to={ROUTES.HOME} replace />;
      }
      return children ? children : <Outlet />;
    };

2. ESLINT ERROR & BUG: BROKEN LOGOUT AND UNUSED DISPATCH
--------------------------------------------------------------------------------
Location:
  File: src/components/Navbar.jsx
  Lines: ~17-40

Problem:
  ESLint reported:
    'dispatch' is assigned a value but never used (no-unused-vars)
  
  Additionally, there was a logical bug in `handleLogout`:
    import { logout } from "../features/AuthFeatures/authSlice";
    ...
    const handleLogout = () => {
      logout();
      navigate(ROUTES.LOGIN, { replace: true });
    };
  `logout` was imported directly from `authSlice`. In Redux Toolkit, calling an
  action creator like `logout()` without `dispatch(logout())` does nothing to 
  the Redux store. Meanwhile, `useAuth()` already provides a fully functional
  `logout` helper that clears `localStorage` and dispatches the action.

Solution:
  1. Extracted `logout` from the `useAuth()` hook: `const { user, logout } = useAuth();`
  2. Removed unused `useDispatch` import and hook call.
  3. Removed unused `logout` action creator import from `authSlice`.
  4. Updated `handleLogout` to call the hook's `logout()` and close menus.

4. AUTHENTICATION BUG: USER SESSION LOST ON PAGE REFRESH
--------------------------------------------------------------------------------
Locations:
  File 1: src/services/authService.jsx (saveRegisterUser)
  File 2: src/components/LoginForm.jsx (onSubmit sessionUser)
  File 3: src/features/AuthFeatures/authSlice.jsx (getInitialAuth)
  File 4: src/hooks/useAuth.js (restoreUser)

Problem:
  `getInitialAuth` and `restoreUser` required `authUser.id && authUser.email`:
    if (authUser && authUser.id && authUser.email) { ... }
  However:
  - `saveRegisterUser` in `authService.jsx` did not generate an `id` when users
    registered.
  - When users logged in, `foundUser.id` was `undefined`, storing an object
    without an `id` in `localStorage` under `auth_user`.
  - On page refresh, `getInitialAuth` and `restoreUser` checked for `id`, failed
    the check, cleared `auth_user`, and logged the user out.

Solution:
  1. In `src/services/authService.jsx`: Added `id: data.id || Date.now()` fallback.
  2. In `src/components/LoginForm.jsx`: Added `id: foundUser.id || Date.now()` fallback.
  3. In `src/features/AuthFeatures/authSlice.jsx`: Changed check to `authUser && authUser.email`.
  4. In `src/hooks/useAuth.js`: Changed restore check to `savedUser && savedUser.email`.

--------------------------------------------------------------------------------
5. REACT HOOK WARNINGS: RE-CREATING ARRAYS IN COMPONENT RENDERS
--------------------------------------------------------------------------------
Locations:
  File 1: src/components/Menu.jsx (foodItems & useMemo at ~377)
  File 2: src/components/Restaurant.jsx (restaurants & useMemo at ~270)

Problem:
  ESLint React Hooks rule reported:
    React Hook useMemo has a missing dependency.
    The array makes the dependencies of useMemo Hook change on every render.
  Static data arrays (`foodItems`, `restaurants`, `categories`) were declared
  inside the component body. On every re-render, new array references were
  allocated in memory, defeating the memoization optimization.

Solution:
  Hoisted the static data arrays (`foodItems`, `categories`, `restaurants`) outside
  the component functions to module-level scope. This ensures stable references,
  eliminates unnecessary re-allocations on render, and satisfies ESLint.
